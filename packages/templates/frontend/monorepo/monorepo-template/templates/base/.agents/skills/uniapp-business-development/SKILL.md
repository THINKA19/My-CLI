# uni-app 项目规范

## 定位

本 Skill 封装本项目自己制定、长期维护的六份规范。references 中的文档是唯一正式正文；本入口只说明读取与执行方式，不另设一套替代标准。

## 读取规则

- 业务设计、开发或重构：读取[架构原则](references/architecture-principles.md)与[业务组织规范](references/business-architecture.md)。
- 任何代码生成、修改、封装或重构：必须读取并执行[代码注释规范](references/code-documentation.md)，保留完整文件顶部注释、方法级注释与使用示例。
- 涉及请求、上传、认证、错误或传输实现：同时读取[HTTP 规范](references/http.md)。
- 涉及页面、路由、导航、分享或角色分包：同时读取[页面地图](references/page-map.md)。
- 涉及构建、版本、产物检查或发布：同时读取[构建与产物检查](references/build-release.md)。
- 维护规范本身：读取被修改文档与引用它的相关规范，避免名称、契约和要求相互冲突。

## 执行要求

1. 先读取目标项目适用的 AGENTS.md 与有关脚手架规范，再核对源码、公开入口和配置。文档内的 src/、hermes/、package.json 等路径相对于目标应用根目录；承载本 Skill 的目录不一定包含完整应用。
2. 保留本项目已经制定的目录、公共边界、必备文档、注释模板和验收要求；不能以通用化或精简为由自行删除或降级。发现实现与规范冲突时明确差异，按用户授权范围处理。
3. 页面清单按文中核实时间理解；构建命令和公开 API 使用前核实是否已实现。没有源码或运行环境时如实说明未验证，不据文档宣称能力已经可用。
4. 用户要求先讨论时只交付方案；授权修改后完成范围内实现及必要验证。不因使用此 Skill 扩大重构或发布范围。
5. 修改规范只维护 references 中的正式版本，同时更新相关引用。交付说明改动、验证结果与未验证项。

## 调用

“使用 $uniapp-business-development，按项目规范完成本次业务修改，并严格执行代码注释要求。”
