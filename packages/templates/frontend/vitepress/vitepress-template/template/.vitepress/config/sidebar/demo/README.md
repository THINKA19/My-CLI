# 菜单扩展示例

本模块是实际可浏览的手动配置示例，不使用自动菜单生成。

- 7 个顶层导航入口：首页和 6 个分类。
- 导航树共 39 个节点，覆盖直接链接、下拉菜单、分组标题、外部链接、邮箱、查询参数和锚点。
- 6 个独立侧边栏分区，每区 10 个文档入口，共 60 个。
- 三种语言各有 60 篇分类示例，顶层仅保留 index.md 和分类文件夹。
- 示例邮箱 docs@example.com 为占位地址，不是真实客服联系方式。

## 浏览

在项目根目录运行 `pnpm dev`，打开终端显示地址下的：

- `/zh/`
- `/en/`
- `/vi/`

根路径自动进入默认语言首页。通过首页分类卡片或顶部分类下拉菜单进入文档。
进入分类后显示该分类自己的侧边栏。
configuration 展示分组导航，development 展示页面锚点，deployment 展示查询参数；
getting-started 是平铺侧边栏，其余分类展示嵌套分组和折叠状态。

## 文件对应关系

```text
config/nav/demo/分类.ts                    导航结构
config/sidebar/demo/分类.ts                侧边栏结构
config/locales/语言/nav/demo/分类.ts        导航文案
config/locales/语言/sidebar/demo/分类.ts    侧边栏文案
src/语言/分类/page-01.md                    实际页面
```

nav/demo/index.ts 组合分类导航；sidebar/demo/index.ts 注册分类前缀。
每种语言的 demo/index.ts 汇总对应文案，上层 index.ts 只注册整个 demo 模块。
每个栏目使用独立 key 命名空间，同一菜单的结构与文案由类型约束关联。

## 扩展到更多页面

新增分类：增加该分类的 nav/sidebar 文件、各语言文案和页面，再在 demo/index.ts 注册。
只有需要的菜单类型才创建文件；不要求每个栏目都有顶部导航。

单个分类达到几百项或包含独立子模块时，把 分类.ts 升级为 分类/index.ts，
再拆成 core.ts、plugins.ts 等短文件；保持原来的导出名称，上层组合方式不变。
翻译采用相同逻辑分区，并保留 `satisfies MenuText<typeof 结构>` 约束。

几千项侧边栏仍按路径分区展示；导航入口较多时放进分组，避免把所有入口铺在顶栏。
文件拆分验证维护方式，不代表浏览器会自动按需加载全部菜单配置。

## 验证与移除

运行 `pnpm test:i18n`；测试位于 tests/i18n/config.test.mjs，检查分类、数量、路径、菜单类型和文件长度。
现有的 3,000 节点解析测试继续保留，用于测试同一解析接口的规模扩展。

正式项目不需要这些示例时，移除上层 nav/sidebar 和各语言汇总入口中的 demo 引用，
再删除对应配置 demo 目录、三种语言的分类目录和示例专用测试。
