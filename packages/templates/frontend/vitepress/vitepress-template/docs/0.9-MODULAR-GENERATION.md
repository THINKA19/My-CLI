## 发布四部曲

* 步骤1：登录

```bash
pnpm login --registry=https://registry.npmjs.org/
```

*  步骤2：验证登录是否成功

```bash
pnpm whoami --registry=https://registry.npmjs.org/
```

* 步骤3：设置token

```bash
 pnpm config set //registry.npmjs.org/:_authToken=你的新Token --global
```

* 步骤4：发布

```bash
pnpm publish --access public
```



# 模块化生成设计

## 范围

本次将现有模板迁移为可选模块，保留菜单算法、Mermaid 渲染、部署校验及各平台发布实现。必要变更包括：单语言路由适配、语言子集组装、共享菜单工具路径调整、依赖和工作流引用裁剪。不新增动画库、部署平台、SSH 静态文件部署，也不升级依赖。

## 文件计划

所有问答完成后，先组装内存中的文件计划。基础文件、语言及功能模块逐项加入，`package.fragment.json` 仅合并到最终清单，不复制到用户项目。`.tpl` 渲染为实际配置，平台说明按选择生成。确认目标目录及摘要后才写入文件。

目标非空时拒绝写入，允许 `.git` 和 `.DS_Store`。拒绝经符号链接重定向的目标路径，不覆盖已有项目或父级仓库配置。

## 语言

单语言只生成所选文案及 `src/` 页面，根路径为 `/`，不注册 VitePress locales，也不生成根入口跳转组件或多语言 sitemap。共享菜单工具位于 `.vitepress/config/menu/`，不依赖启用多个语言。

多语言只加入选中语言，至少两种。默认语言对应 `configKey: root`，各语言 fallback 指向所选默认语言，实际页面仍使用 `/{code}/`。沿用已有导航、侧边栏、搜索、SEO 和 sitemap 实现。

## 可选能力边界

- Mermaid 的 Markdown、主题和样式同时加入或移除。
- Git 提交检查独立提供提交消息校验；暂存文件 ESLint 检查只在 ESLint 同时启用时生成。
- CI 仅执行实际可用的检查。全平台维护回归留在脚手架测试，不强制加入基础用户项目。
- GitHub Pages 入口和执行子流一起生成。镜像发布未选服务器时去掉服务器子流调用。
- Docker、服务器和镜像发布分别选择；服务器部署自动补齐 Docker 和镜像发布前置条件。
- 单独平台仅引入自身 SDK，公共部署工具保留原实现。
- pnpm 11 锁文件包含两个 YAML 文档；仅筛选项目 importer 的直接依赖，保留原版本及完整传递依赖快照。

## 验证

快速测试覆盖三种单语言、多语言子集及默认语言、可选依赖、CI/hooks 组合、部署工作流本地引用、锁文件、当前目录创建与非空冲突、workspace 和问答约束。

集成测试对三种单语言、无中文的多语言子集及全功能项目执行菜单生成、菜单回归、类型检查和生产构建；全功能项目额外执行原有国际化与部署回归。云端发布需要真实账号与凭据，不由本地测试代替。

`docs/0-ARCHITECTURE.md` 和 `docs/1-ARCHITECTURE.md` 是迁移前的历史设计，本文件描述当前结构。
