# 全平台部署测试

## 本地与 Actions 验证

在生成项目的根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test:deploy
```

设置目标平台的进程环境变量后，运行 `pnpm deploy:check vercel`。
目标支持 pages、vercel、cloudflare、oss、cos、docker、server。
检查只显示缺少的变量名称，不显示凭据值；通过只说明配置存在且部分格式有效。
Pages 账号权限和仓库 Source 必须由真实发布验证，不能通过本地配置检查证明。

main 推送、PR 会自动启动“测试 / 全平台部署适配（不发布）”，也可在 Actions 手动运行。
该测试不受任何部署 ENABLED 开关控制。它验证：

- 五个静态平台的构建，Pages/OSS/COS 同时验证根路径和子路径。
- 检查语言首页、404 产物、本地资源文件以及 sitemap 的域名和路径。
- Vercel 输出转换、上传失败停止发布 HTML、CLI 生成项目和缺失配置回归。
- Docker 根路径与子路径镜像构建，容器健康接口、三个语言首页和 HTTP 404。

矩阵中的静态平台共用 VitePress 构建，并不模拟平台的托管服务或验证云端凭据。
本地构建后，也可保留对应 VITE_BASE 和 VITE_SITE_URL，运行
`node scripts/deploy/verify-output.js` 验证静态产物。
未开启的实际部署属于“跳过”，缺少云端资源属于“未执行”，均不计为成功。

## 真实发布验收

为每个平台创建独立测试项目或存储桶，使用测试域名；不要直接使用正式站点。
按 [部署指南](DEPLOYMENT.md) 配置对应 Variables 和 Secrets，只开启需要的目标。
配置服务器时 SERVER_IMAGE 必须与已开启、已推送 SHA 标签的镜像目标一致。

依次手动运行对应网站部署工作流。Docker 分别验证阿里云、腾讯云和 Docker Hub
镜像推送，然后在测试服务器验证拉取、启动、健康检查和失败回退。
服务器部署工作流本身不会构建镜像。

每次部署后访问真实网址，检查首页、三种语言首页、至少一个深层页面的直接刷新、
JS/CSS/图片加载、404 状态、canonical 和 sitemap 域名及路径。
再修改一个页面并发布，确认云端显示新版本，避免仅验证首次上传。
OSS/COS 还须验证静态托管和无扩展名路由规则。
